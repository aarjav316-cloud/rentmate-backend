Key Observations:

  ΓÇó MongoDB automatically creates an index on _id ΓÇö no manual index needed.
  
  ΓÇó The { status: 1 } single-field index has LOW selectivity.
    Most properties are AVAILABLE, so the index doesn't filter out many docs.
    It is SUBSUMED by the compound index { status: 1, location.city: 1, rent: 1 }.
    ΓåÆ REDUNDANT unless standalone status queries exist (they don't).

  ΓÇó The { propertyType: 1 } single-field index is rarely queried alone.
    It always appears alongside status. As a single-field index it has 
    limited value; the optimizer might use it but status + type would be better.
    ΓåÆ LOW VALUE for current patterns.

  ΓÇó The { location.city: 1 } single-field index is SUBSUMED by the compound
    index { status: 1, location.city: 1, rent: 1 } for the most common query  
    (status + city). However, city filters use case-insensitive regex (/^city$/i),
    which can still use the B-tree index for prefix anchored patterns.

  ΓÇó The { rent: 1 } single-field index can help for sort-by-rent queries
    when no other filters are applied. However, it does not help rent RANGE
    queries that also filter by status, because MongoDB uses one index per query
    and the compound index { status: 1, location.city: 1, rent: 1 } would need
    to be used instead.

  ΓÇó The compound index { status: 1, location.city: 1, rent: 1 } follows the
    Equality-Sort-Range (ESR) pattern well for queries that filter by status + city
    and then range on rent. This is the MOST VALUABLE index for the discovery API.

  ΓÇó Keyword search ($or with unanchored regex) CANNOT use B-tree indexes.
    Regex patterns like /vijay/i (no ^ anchor) require a COLLSCAN or an  
    expensive index scan. This is a known MongoDB limitation.
    ΓåÆ MongoDB Text Index or Atlas Search would be needed for production scale.

  ΓÇó skip-based pagination degrades for large page numbers because MongoDB must
    iterate through (page-1)*limit documents before returning results.
    ΓåÆ Cursor-based pagination should be considered if the dataset grows large.

Redundancy Assessment:
  ΓÇó { status: 1 }              ΓåÆ REDUNDANT (prefix of compound index)
  ΓÇó { propertyType: 1 }        ΓåÆ LOW VALUE for current query patterns
  ΓÇó { location.city: 1 }       ΓåÆ MOSTLY REDUNDANT (compound index covers most cases)
  ΓÇó { rent: 1 }                ΓåÆ USEFUL for sort-by-rent when no city filter
  ΓÇó { createdBy: 1 }           ΓåÆ ESSENTIAL for getMyProperties
  ΓÇó compound { status, city, rent } ΓåÆ MOST VALUABLE
